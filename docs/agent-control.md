# Agent control: instruction + enforcement

**Instruction — `.claude/skills/keep-app-working/SKILL.md`.** Fires whenever a change touches `datalogger_client/ui/`, `datalogger_client/io_layer/`, or `main.py`, whether or not the task is phrased as a GitHub ticket — the point is that a diff can silently break a feature it never mentions, so the agent runs the full suite and checks that the chart toggle, the manual-override sidebar, the Firebase upload, and the three Connection states still work. It should **not** fire for docs-only changes (e.g. editing `README.md`) or for read-only questions about existing UI code (e.g. "explain how `main_window.py` decides Stale") — both were tested and correctly stayed out, confirmed in `docs/agent-control-evidence.md`.

**Enforcement — `.claude/hooks/block-dangerous-git.sh`, wired as a `PreToolUse` hook in `.claude/settings.json`.** Blocks `git push` (including `--force`), `git reset --hard`, `git clean -f[d]`, `git branch -D`, and `git checkout .` / `git restore .` before the shell ever runs them. Instruction alone was already documented and already insufficient: `.claude/skills/implement-ticket/SKILL.md` has said for several commits that "pushing is the user's job; a hook blocks `git push`" — but no hook existed, so that line was a promise the repo wasn't keeping. Wording can be forgotten, misread, or simply not apply to a differently-phrased request; a push either happens or it doesn't, so this is exactly the "must never happen, no exceptions" case the instruction path can't guarantee.
